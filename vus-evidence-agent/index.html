The problem this solves

Variants of Uncertain Significance (VUS) are the daily bottleneck of clinical genomics.

Predictors disagree. Most published models are trained and tested on random ClinVar splits — which leaks variants that were reclassified using the same evidence the model is then credited for learning. And an AUROC of 0.99 tells a lab nothing about whether a “90% pathogenic” call is right 90% of the time.

The gap is not another AUROC point. The gap, as the project’s README states it, is three things at once:

  • Temporal validity — train on classifications frozen at a cutoff, test only on variants reclassified after it.
  • Calibration — a probability that means what it says, reported per gene family (ECE / Brier), including where calibration fails.
  • Evidence provenance — every claim in a report cited to a retrieved record, with an explicit allowed answer: “insufficient evidence — remains VUS.”

Data — a temporal split, built from dated ClinVar releases

All data is open and pinned by date, because the temporal split depends on it. The cutoff snapshot held 2,366,650 GRCh38 rows; the current snapshot holds 4,578,190. The split report (data/processed_v2/SPLIT_REPORT.md) records exactly what fell on each side of the freeze:

  • Train — 1,103,657 variants labelled at the Jan 2024 cutoff and frozen: 240,752 pathogenic, 862,905 benign.
  • Test — 27,748 variants that were uncertain at the cutoff and have since been reclassified: 8,856 pathogenic, 18,892 benign. No test label existed at train time.
  • Near-duplicate guard: test rows sharing gene + name with train are removed — the guard removed 0 rows.

Why random splits leak (from docs/leakage-audit.md)

A variant reclassified in 2024 was often reclassified using the same predictor scores and submissions that appear as features. Random splits put that variant — or its near-duplicates — in both train and test: the model is graded on evidence it has already seen. The audit was written before any model code: pin a dated release, train on classifications frozen at the cutoff, test only on variants whose classification changed after it, and join features as of the cutoff where the source allows dating — and say so per feature where it does not.

Predictor coverage (from FEATURE_REPORT.md)

AlphaMissense is precomputed and missense-only, so coverage is partial by construction: it scores 37.4% of the test set (30.0% of benign, 53.2% of pathogenic) and 12.6% of train. Every model result below is on the scored subsets — 138,972 train rows and 10,373 test rows carry an AlphaMissense score. The scores are linked from the source, not redistributed: the downloaded file’s own header reads CC BY-NC-SA 4.0 while other sources say CC BY 4.0, and the project keeps the ambiguity stated rather than resolved in its own favour (see docs/licence-notes.md).

gnomAD — population context, with a documented caveat

The gnomAD file downloaded for allele context turned out to be locus-level allele number only — no allele count, no allele frequency for a specific variant allele (docs/gnomad-note.md). The project does not use it as an AF feature and says so, rather than relabelling coverage as frequency. True AF joins later via per-chromosome sites VCFs or the API; the models below stand without AF until then.

Coverage is the binding limit: the predictors are missense-only, so most of the declined variants are non-missense variants with no predictor score at all. A decline is a designed output, not an error.

Method

Features: predictor scores and a gene prior

Two feature families feed the models. AlphaMissense provides a precomputed pathogenicity score per missense variant (weights are not released, so there is no scoring of novel variants beyond the precomputed predictions). The gene prior is computed from the frozen train labels only — smoothed, m = 10 — and genes unseen in train fall back to the global train rate, 0.379. REVEL joined later as a second predictor: v1.3 from its public Zenodo record, MD5 verified against the record, taking the maximum across transcripts per the dbNSFP convention, stated openly in the report.

Ensemble

The models began as a logistic ensemble over the AlphaMissense score and the gene prior. Three names recur in the reports and on this page: Model 2 is that logistic ensemble with isotonic calibration — the earlier logistic model, and the one the live app served until 2026-10-26; M2+R is the same logistic model with REVEL added as a third feature; GBM+R is gradient boosting over the same three features. On 2026-10-26, Model Report 6 re-ran every candidate head-to-head on the same frozen test and adopted GBM+R as the final model. Probabilities from a raw model are not trusted as probabilities until they survive calibration; discrimination (AUROC) and calibration (ECE, Brier) are reported as separate claims for every model variant, including the ones that got worse.

Calibration

Two calibration maps are compared throughout: Platt scaling and isotonic regression, each fitted on train data only — never on the test set. Calibration quality is reported overall and per gene family (genes with n ≥ 50 scored test variants), because an aggregate number can hide badly miscalibrated subgroups.

A from-scratch MLP, tried and reported

Model Report 3 documents a hand-built alternative: a 2-16-16-1 tanh MLP in raw NumPy (seed 13, 300 epochs, loss 0.703 → 0.266), with the gene prior gated by exp(−|am − 0.5| × 4) so the prior only speaks where AlphaMissense is uncertain. Permutation importance on the test set: AlphaMissense score 0.360, gated prior 0.043. Its results are in the table below; the report’s own reading is that more model is not more truth.

A method trap, documented in Model Report 4

Building the gene prior from all frozen-train rows instead of only the AlphaMissense-scored rows silently drops AUROC to 0.933–0.935 (Brier 0.101). The prior has to describe the scored population the model actually serves, not the whole database. The trap is written into the report so it stays visible.

Calibration under the temporal test

Model Report 1 states the principle the whole project runs on: the point of calibration is that ECE and Brier improve and the number means what it says — and if they don’t improve, that is reported too. On the temporal test, the first calibration attempt did not improve. Platt scaling fitted on the 2024 training window was applied to variants reclassified after the freeze, and the probabilities got worse:

ECE 0.040 Uncalibrated, on the post-freeze test set. Brier 0.113.
ECE 0.157 Worse, not better — Brier 0.141. AUROC is unchanged at 0.921, because Platt is a monotonic transform: ranking survives while the probabilities stop meaning what they say. Per-gene ECE ran 0.203–0.428.
ECE 0.017 Isotonic recalibration fitted on a training holdout, judged against the same untouched test set. Brier 0.078. The final model — GBM+R, gradient boosting with REVEL added, isotonic-calibrated — reports ECE 0.025 and Brier 0.062.

The failure only appears because the test set is temporal. A random split grades the model partly on evidence it has already seen, and a calibration map that does not transfer forward in time can still look fine. The split design — freeze, then test only on what was reclassified afterwards — is what makes the failure, and then the improvement, visible at all.

The reports also record the project catching its own error: the first committed version of Model Report 3 printed ECE values computed with an argument-order bug in the ECE call (labels passed where probabilities belong). A reproduction audit of Model Report 2 caught it; the affected values were recomputed, AUROC and Brier were unaffected, and the correction note is kept in the report.

The evidence agent

The agent sits on top of the calibrated model. Retrieval runs over frozen ClinVar records and predictor records; the agent drafts an ACMG-style summary in which every claim is cited to a retrieved record — the cite-or-decline rule is enforced in code (src/vus_agent/agent.py), not left to the model’s discretion. Where the retrieved evidence does not support a summary, the allowed output is a decline: “insufficient evidence — remains VUS.” An adversarial test in the repo (tests/test_agent_refuses.py) feeds the agent a fabricated citation and a missing record; it must decline both.

Agent coverage on the 27,748-variant test set10,357 reported · 17,391 declined
37.3% reported — 10,357 variants summarised with cited evidence 62.7% declined — 17,391 variants, most of them non-missense with no predictor score at all; extending coverage to splice and non-coding variants is next on the roadmap

The decline rate follows from coverage: the agent may summarise only variants with a retrieved predictor record, and 62.7% of the test set has none the final model can score. The reports file (examples/agent_reports_real.md, generated by scripts/run_agent_real.py) publishes real outputs from the test set — including the confident calls, the declines, and the misses. Limits

The README’s limits section is headed “say them out loud.” They are:

  • Temporal reclassification labels are themselves partly predictor-influenced. The temporal split removes the direct leak; it does not make labels pure. That circularity is discussed, not hidden.
  • AlphaMissense scores cover missense only, precomputed only. Weights are not released, so there is no novel-variant scoring beyond the precomputed predictions — which is also why the agent declines the majority of the test set.
  • A calibrated probability is not a clinical classification. ACMG classification remains a human, guideline-driven judgement.
  • gnomAD allele frequency is not in the model. The downloaded allele-number file is locus-level AN only and cannot yield AF; the project ships without AF rather than relabelling coverage as frequency, with the VCF/API route documented as the deferred path.
  • dbNSFP was deferred, and the scores are linked, not redistributed. Bulk dbNSFP download needs institutional-email registration; REVEL was taken from its public Zenodo record instead. AlphaMissense licence wording is ambiguous between sources, so the score file is linked to, never redistributed.

Validation dossier

The repo assembles its validation evidence into a single dossier (docs/validation-dossier.md), drawn entirely from the project’s own split, feature, and model reports. It covers the same ground a documentation package for a clinical-grade system carries — intended use, validation design, performance including the worst cases, failure modes, and the oversight design — in the project’s own terms:

Status — stated in the dossier’s header

This is a research system, not a certified medical product. Clinical deployment would require formal validation and regulatory clearance. The intended use is evidence summarisation for variant interpretation research — a reviewer aid. Every report carries the verdict line “evidence summary (not a clinical classification)”.

Validation design

A temporal split from dated ClinVar releases: train on 1,103,657 classifications frozen at Jan 2024; test only on the 27,748 variants reclassified after the freeze, with a near-duplicate guard between the splits. The design exists because random splits leak — reclassifications made using predictor scores reappear as features on both sides. The dossier also keeps the caveat the split report states: the post-freeze labels are themselves partly predictor-influenced.

Performance, including the worst genes

The final model (GBM+R, adopted 2026-10-26 in Model Report 6 and recorded in the dossier’s §7 addendum) reports AUROC 0.970, ECE 0.025 and Brier 0.062 on the 10,357 scored variants of the temporal test set, and the dossier carries the full ablation, including the rows that got worse (raw ensemble ECE 0.251; Platt on the training window, 0.157). Per-gene calibration is reported gene by gene: most large genes sit between ECE 0.005 and 0.154, and the worst, USH2A at 0.204, is named as a calibration failure rather than averaged away.

Failure modes, as published

The dossier collects the misses the project itself published: a confidently benign-leaning summary at P = 0.002 under the earlier logistic model (0.006 under GBM+R) for a variant (RANBP2 c.1754C>T) later reclassified pathogenic; three under-confident calls at P = 0.493 under that model (HOGA1, PROC, GLB1) on variants later classed pathogenic — resolved under GBM+R at 0.808 and 0.979, while PROC remains under-confident at 0.464; and the structural limits — predictor coverage of 37.4% of the test set, missense and precomputed scores only, no gnomAD allele frequency, and labels that are partly predictor-influenced.

Human oversight design

The rules are enforced in code, not in a prompt: every claim must cite a retrieved record or the report is not emitted; below MIN_EVIDENCE = 3 distinct evidence items the only output is “insufficient evidence — remains VUS”; an adversarial test feeds the agent a fabricated citation and a missing record and requires a decline both times. The calibrated probability is never presented as a classification — ACMG classification remains a human, guideline-driven judgement.

Running and reproducing

The project runs on CPU with fully public data, and a Dockerfile is provided. The demo needs no downloads and runs in about ten seconds — it uses a small synthetic variant table to show the full loop: features → calibrated probability → cited evidence summary → and the refusal path when evidence is insufficient:

PYTHONPATH=src python3 -m vus_agent.demo
PYTHONPATH=src python3 tests/test_agent_refuses.py

The full pipeline reproduction — the scripts behind every number on this page — runs from the downloaded ClinVar and AlphaMissense files:

python3 scripts/build_temporal_split.py
python3 scripts/join_alphamissense.py
python3 scripts/train_ensemble.py        # Model Report 2: AUROC 0.958, ECE 0.017
python3 scripts/join_revel.py            # REVEL v1.3, public Zenodo record
python3 scripts/train_revel_ablation.py  # Model Report 4: AUROC 0.968
python3 scripts/eval_headtohead_20261026.py  # Model Report 6: GBM+R adopted, AUROC 0.970
PYTHONPATH=src python3 scripts/run_agent_real.py

The Docker image (python:3.12-slim) installs the requirements, copies the source, and runs the demo as its command. Real run output — the demo, the agent on real variants, and a refusal — is collected in examples/DEMO.md.

Scope

How to use

Single lookup

Enter one variant and read its stored report: the calibrated probability from the final model and the evidence summary in which every claim is cited to a retrieved record — or an explicit decline, “insufficient evidence — remains VUS”, where the evidence is not there.

Live-evidence mode

Run the agent against live retrieval for a variant: it gathers the records that bear on the variant and applies the same rule — cite, or decline. A minimum of 3 distinct evidence items is required before the agent says anything at all.

Batch pack

Submit a set of variants and receive an evidence pack: one cited summary per variant that clears the evidence bar, with each remaining variant declined individually rather than summarised on thin evidence. On the temporal test set the agent summarises 10,357 of 27,748 variants and declines 17,391.
